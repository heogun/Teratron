# 하드웨어 설계 결정·보류·후속 과제

이 문서는 칩 수 논의부터 PS/2 보류까지의 설계 결정을 기록한다.
상위 사양은 루트 `hardware_specification.md`, 수량 배정은 [BOM 기준](hardware_bom.md),
현재 실행 중인 기능 모델은 [emulation.md](emulation.md)를 따른다.

## 1. 상태를 구분하는 원칙

- **결정/채택:** 사용자가 정한 구조·부품·수량 배정. 수동소자값 미선정과 혼동하지 않는다.
- **구현·검증 작업:** 결정한 구조 안에서 핀/게이트 연결, 값 산출, 파형·최악조건 검증을 수행할 일.
- **구조적 선택이 남음:** 실행 모델이나 인터페이스 중 실제로 선택하지 않은 대안.
- **보류:** 선택한 구성을 보존한 채 논의를 멈춤. PS/2가 해당한다.

이 논의에서는 전체 핀 단위 회로도·게이트별 넷리스트·SPICE 파형·실측 결과가 생성되지 않았다.
설계 기준 확정과 전기적 동작 검증 완료를 서로 대체해서 표현하지 않는다.

## 2. 채택한 시스템 구성

### 원본 재사용과 메모리

- Gigatron BOM/회로를 최대한 재사용하며 원본 파일은 보존한다. 논리 IC는 HC로 통일한다.
- 게임 컨트롤러 인터페이스는 제거하고 순수 논리 PS/2로 대체한다. ATtiny 어댑터는 사용하지 않는다.
- 데이터 RAM: AS6C1008-55PCN ×1, 64KiB 고정/무뱅킹, A16=0. 기존 62256 핀/CE 배선은 조정한다.
- I-RAM: AS6C4008-55PCN ×2, Flash: SST39SF040-70-4C-PHE ×2.
  각각 512K워드 ×16비트 = **1MiB**, opcode/operand 두 레인, 전체 용량 사용.
- PC 16비트는 뱅크 안의 64K워드 주소다. A16–A18의 3비트로 실행 뱅크 8개를 선택한다.
- 공유 뱅킹용 74HC161 ×1을 채택했다. 273을 대체하며, 부팅 때 계수하고 정상 실행 때 병렬 로드한다.
  병렬 로드는 클록에 동기식이다. `/PE` 자체의 에지가 값을 저장하는 것은 아니다.
- 추가 74HC157 ×4로 PC/CPU 데이터 주소를 선택한다. 원본 D-RAM용 157 ×4는 그대로 별도다.
- CPU는 항상 8비트 데이터 버스다. 74HC245 ×2로 두 명령어 바이트 레인을 번갈아 접근한다.
- 추가 74HC138 ×1은 유지한다. 데이터 RAM, I-RAM, Flash 접근을 구분한다.
  일반 저장은 데이터 RAM으로 가며 컴파일/명시적 I-RAM 조작만 I-RAM을 변경한다.

### 부팅과 SAVE

- 부팅은 PC 74HC161 네 개를 하위 주소 카운터로 재사용한다. 별도 하위 DMA 카운터 추가 0개.
- PC 전체 carry로 뱅킹용 161을 증가시켜 8개 뱅크를 복사한다. 두 레인을 동시에 복사하는 기준이다.
- 채택한 부트 제어 구성: 74HC74 ×1, IR 리셋, opcode bit 1 OR, 부팅 쓰기 위상 제어.
- `0x02`는 LD AC, AC이며 부트 중 순차 실행용 NOP로 사용한다.
  실제 Gigatron STORE opcode는 `110`, RAM 버스 선택은 `01`, AC 선택은 `10`이다.
- 뱅크 카운터 Q3로 완료를 검출하는 안을 사용한다. 리셋/정상 fetch로의 정확한 전환 순서는 아래 후속 과제다.
- 한 워드/클록이면 전체 복사 명목 시간은 524288 / 6250000 ≈ 83.9ms다.
  한 뱅크는 64K워드 = 128KiB로 약 10.5ms이며, 64KiB가 아니다.
- SAVE는 처음부터 소프트웨어 CPU 루틴이다. Flash 소거, 각 칩 주소 기준 unlock/byte-program,
  DQ6 완료 확인, 읽기 검증을 수행한다. 단순 SRAM식 덤프가 아니다.
- XOUT LED 비트 하나를 Flash 쓰기 허용으로 전용한다. 허용 비트와 실제 `/WE` 펄스는 분리한다.
- Flash는 I-RAM만 저장한다. 데이터 RAM 백업, 전원 감지, 자동 SAVE, 전원 차단 인터럽트는 없다.
  SAVE 중 전원 차단은 정의하지 않으며 복구/원자성 보장은 없다.

## 3. PS/2: 구성 고정, 상세 선정은 보류

PS/2는 사용자 지시로 현재 보류한다. 다음 선택을 보존하고, 소자값 때문에 다시 미정으로 표현하지 않는다.

### 부품·기능

- 74HC595 ×2, 74HC161 ×1, 공유 74HC14 ×1.
- NPN ×2: CLK host inhibit용 1개, 워치독 커패시터 능동 방전용 1개.
- NAND SR 래치와 상태/워치독 논리는 배정된 74HC00·74HC32·74HC14의 여유 게이트 활용.
  추가 전용 D-FF/모노스테이블 IC는 넣지 않는 기준이다.
- 패리티 검사 생략. 시작·데이터 8개·패리티·정지의 11비트 수신 자체는 유지한다.
- 반전/정형한 PS/2 CLK로 원래 하강 에지에 595 시프트와 161 계수를 수행한다.
- 카운트 11에서 count-enable을 차단한다. 이후 inhibit이 만드는 인위적 하강 에지도 추가 계수하지 않는다.
- 11번째 원본 상승 에지에서 완료를 확정하고 595 출력 래치를 갱신한 뒤 inhibit을 건다.
  다음 12번째 클록을 기다리는 방식은 사용하지 않는다. READY 중 출력 래치를 재갱신하지 않는다.
- NAND 두 개의 SR 래치로 READY/INHIBIT 상태를 유지한다. SET/RESET 극성과 동시 활성 금지를 연결에 반영한다.
- CPU 읽기 완료 후 수신기를 초기화·재준비하고 최소 유지 조건을 만족한 뒤 inhibit을 해제한다.
- 스캔코드 1바이트 래치를 유지하며 하드웨어 FIFO를 추가하는 설계가 아니다.

### 워치독과 타이머: 서로 다른 목적

- 워치독 enable은 `NONZERO AND NOT READY`.
  4비트 nonzero는 2입력 OR 3개, 조건 결합은 논리 1개를 사용한다.
- idle(count=0)의 HIGH는 정상이다. 수신 중(count 1–10)의 HIGH/LOW 고착은 모두 복구한다.
- 에지 미분/AC 결합, 전류 제한, 레일 클램프, 기준 전압 복귀 경로를 둔다.
  펄스가 NPN을 켜서 워치독 타이밍 커패시터를 재충전 주기마다 충분히 방전시킨다.
- 워치독은 정상 비트 간격보다 충분히 긴 3–5ms 목표다. timeout이 완료된 미소비 데이터를 지우지 않는다.
- inhibit 유지 타이머는 별개이며 최악조건 최소 100µs 이상을 목표로 한다.
  CPU 읽기 뒤에도 유지하는 RC 지연안을 채택했다. 공칭 150–200µs 등은 논의된 목표이지 측정 결과가 아니다.
- `t=RC`를 실제 트리거 시간으로 사용하지 않는다. 방전식이면
  `t_min=R_min*C_min*ln(V_initial,min/V_T-,max)`로 계산하고 초기 충전 조건을 정의한다.
- 논의된 예시값(워치독 47kΩ/100nF, inhibit 22kΩ/10·15·22nF,
  미분 100·1000pF, 제한 1kΩ)은 **확정 구매값이 아니다**.
  슈미트 문턱, R/C 오차·온도·바이어스, 클램프 전류, 방전량은 재개 후 산출한다.
- BAT54는 쇼트키, 1N4148은 일반 실리콘 다이오드다. 동일 특성으로 취급하지 않는다.
  패키지는 관통형/DIP 제약에 맞춰 선정한다.
- 실제 게이트 번호별 자원 할당, 완료 검출의 글리치 방지, 래치 setup/hold,
  방전 펄스 폭과 잔류 전압, inhibit 진입/해제 파형은 구현·검증 작업으로 남긴다.

## 4. 소자값과 무관하게 남은 시스템 구조 결정

### A. 정상 실행 중 단일 포트 I-RAM 접근 일정 — 최우선

주소 MUX 네 개의 채택은 완료됐지만 fetch와 CPU 접근을 배치하는 실행 일정은 미확정이다.
두 80ns 위상으로 나누고 PC/IR을 하강 에지에 구동하는 안이 제안됐다.
다만 이는 PC 출력 지연만 미리 숨기며 IR→디코더→메모리→버퍼→ALU→목적 레지스터의
실행 경로 전체를 자동으로 80ns 안에 끝내지 않는다. 확정할 내용:

- fetch/data/IR/PC/결과 레지스터의 에지와 순서
- 반주기 내 완료 불가 시 추가 사이클·정지 또는 다른 실행 규칙을 허용할지
- branch delay slot, PC 병렬 로드, 페이지 경계, OUT 갱신의 ISA 보존
- 메모리 입력이 fetch로 바뀔 때 실행 데이터 유지 방법

6.25MHz/1-cycle은 목표이며, 현재 회로로 달성 검증이 끝났다는 뜻이 아니다.

### B. 실행 뱅크와 접근 뱅크

뱅크 0에서 실행하면서 뱅크 1–7을 읽거나 쓰는 동작, 특히 전체 SAVE가 필요하다.
공유 161 하나를 유지할 소프트웨어 실행 규칙 또는 실행/접근 뱅크 별도 저장·선택 중 정해야 한다.
추가 157 하나의 선택기는 두 값을 저장하지 않으므로 접근 뱅크 저장 위치도 필요하다.
동일 뱅크 컴파일 제한은 제안된 타협안일 뿐 전체 SAVE 해법을 대신하지 않는다.

### C. CPU-visible 접근 인터페이스

대상(I-RAM/Flash), 레인, 읽기/쓰기, 뱅크 로드를 어떤 주소·명령·비트로 표현할지 정한다.
138의 A/B/C·enable·각 Y 출력과 상위 주소 일치 조건을 구체화한다.
대화 중 A13–A15나 Y0–Y3 할당은 예시였으며 최종 주소표가 아니다.
Gigatron에 독립 R/W 핀이 있다고 가정하지 않고 CPU 디코더에서 제어를 도출한다.
에뮬레이터 PORT_LO/HI/target 주소표는 실물 채택이 확정된 인터페이스가 아니다.

### D. D-RAM과 장치 주소 중첩

64KiB 물리 RAM은 확정이다. MMIO가 일부 주소를 가릴지, 별도 접근으로 전체를 유지할지 정한다.
현재 에뮬레이터의 FF00–FF0A 11바이트 가림을 실물 정책으로 자동 승계하지 않는다.

### E. 공유 메모리 버스와 제어 매트릭스

I-RAM/Flash의 대응 레인을 공통 연결하는 범위와 부팅 직접 복사 경로를 고정한다.
모드별 주소원, 활성 메모리, 레인 245 OE/DIR, CE/OE/WE를 표로 작성한다.
필수 구분은 boot copy / fetch / I-RAM CPU read / I-RAM CPU write / Flash read / Flash write다.
특히 boot에서 I-RAM CE는 쓰기 가능해야 하며, I-RAM CPU read 때도 OE가 필요하다.
Flash SAVE 전체 동안 I-RAM을 끄지 않는다. 명령 fetch는 I-RAM에서 계속 공급해야 한다.
두 레인의 245를 동시에 CPU 버스로 출력시키지 않고, 읽기/쓰기 전환에 드라이버 충돌을 막는다.

### F. 부팅 시작·완료 상태 순서

구성은 PC 재사용으로 채택됐으며 남은 것은 상태 전이 정의다:

`전원 초기화 → 주소 0 준비 → 전체 복사 → 마지막 쓰기 종료 → 쓰기 금지 → PC/뱅크 초기화 → 정상 fetch`

각 단계에서 PC/IR/뱅크/BootMode를 유지·초기화하는 대상을 결정한다.
부팅 완료 초기화와 전원 초기화를 분리해 BootMode가 다시 켜지지 않도록 한다.
Q3를 74HC74 CLK에 넣고 D=0으로 종료하는 안과 RC 종료 펄스가 제안됐지만,
정확한 reset/enable 연결 및 handoff는 아직 완성되지 않았다.

### G. XOUT 비트 소유권

LED 비트 하나의 Flash write permission 전용은 확정이다. 실제 bit 번호, HSYNC 에지의 AC 래치와
오디오/LED 코드가 이를 보존하는 규칙, SAVE 종료·오류·리셋 시 해제 주체를 결정한다.
허용 비트를 실제 WE에 직결하지 않는다. 리셋/부트 중 쓰기 금지와 정상 CPU 펄스로 제한한다.

### H. VGA 서비스 정책

원본 출력 회로 재사용은 결정됐다. 컴파일/SAVE 중에도 영상·동기를 계속 유지할지,
동기만 유지하고 화면 갱신을 멈출지 등 펌웨어 서비스 정책은 별도 결정이다.
현 에뮬레이터는 협력형이며 계산/SAVE 중 VGA 갱신을 멈춘다.
목표 1-cycle 처리량만으로 영상 파형이나 원본 서비스가 자동 보존되지는 않는다.

## 5. 구조 결정과 별개인 구현·검증 체크리스트

- 지연은 typical끼리 비교하지 않는다. `/WE 종료 최대 지연 + hold ≤ 주소 변경 최소 지연`과
  데이터 입력에 대한 같은 조건을 검증한다. 뱅크 상위 주소는 하위 MUX와 다른 경로일 수 있다.
- 첫 주소 0을 증가 전에 기록하고, 각 FFFF 및 최종 뱅크의 마지막 워드를 쓰고 나서 전환한다.
- 카운터 공통 클록은 논리적 계수를 맞출 뿐 출력 전환의 동시성이나 SRAM hold를 보장하지 않는다.
- IR 캡처와 주소 전환 경계, clock duty/skew, 최소 WE 폭, setup/hold, CE/OE 해제 시간을 확인한다.
- Flash는 레인별 칩 주소 기준으로 unlock/program/poll한다. 선형 바이트 주소를 그대로
  5555/2AAA에 대입하는 오류를 피한다. erase·프로그램 완료·전체 검증을 별도로 수행한다.
- SRAM·Flash 출력 레벨과 5V HC 입력 임계값, 다이오드 디코더, 발진기, 팬아웃을 검증한다.
- 원본 supervisor 유지/RC+슈미트 대체와 패키지 제약을 정리하고 전원 인가 시 WE 안전 상태를 보장한다.
- 별도 소자값 미선정을 부품 구성 미확정으로 표현하지 않는다. 검증에서 실제 변경이 필요하면
  해당 이유와 변경된 부품만 기록한다.

## 6. 폐기·정정한 설명

- I-RAM/Flash 각각 512KiB만 사용한다는 설명 → **각 1MiB 전체 사용**.
- 뱅킹용으로 273 두 개가 필요하다는 설명 → **상위 주소용 하나였으며 현재 161 하나로 대체**.
- 평소 CPU 쓰기가 모두 I-RAM으로 간다는 설명 → **일반 쓰기는 D-RAM**.
- SAVE를 소프트웨어로 하면 물리 버스/선택 회로도 필요 없다는 설명 → 경로는 필요.
- PS/2 NPN 총 1개 → **워치독 능동 방전 추가 후 총 2개**.
- 4입력 nonzero에 2입력 OR 1–2개 → **3개**, NOT READY 결합 별도.
- 74HC14 두 개를 NAND SR 래치와 동일시 → SR은 **NAND 두 개** 사용.
- RC 시정수/typical 문턱만으로 최소 시간을 보장했다는 주장 → 최악조건 산출 필요.
- 부팅·반주기 접근이 PCB 동작 보장까지 끝났다는 주장 → 구성 채택과 파형 검증은 별개.

## 7. 에뮬레이터와 정렬할 후속 작업

이번 변경은 문서화이며 코드/펌웨어/회로 원본을 변경하지 않는다.
에뮬레이터는 I-RAM/Flash 각 512KiB, 실행 뱅크 4개, 1바이트/tick DMA,
524288 tick CPU 정지 후 시작이라는 기존 기능 모델을 유지한다.
실물은 각 1MiB/8개 실행 뱅크/PC 재사용 워드 복사이므로 추후 별도 구현 작업이 필요하다.
기존 MMIO PORT_LO/HI 및 MEMORY_BANK/EXEC_BANK 분리도 최종 실물 인터페이스와 맞춰야 한다.
PS/2 패리티 검증·2ms 오류 처리·overrun은 현재 모델 동작이다. 패리티 생략·RC·host inhibit
선택을 코드에 반영한 것으로 오해하지 않는다. PS/2는 보류 상태이므로 이번에 변경하지 않는다.
