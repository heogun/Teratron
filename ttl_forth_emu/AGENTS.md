# New-machine emulator

- Independent fork of `../gigatron_emu/core/`; do not change the stock emulator. `firmware/build.py` assembles native CPU code plus an I-RAM token-threaded FORTH dictionary; Python/GUI must never evaluate FORTH on the host.
- User overrides to the original specification: data RAM is **64KiB, unbanked** (AS6C4008 A16–A18 grounded); flash stores **I-RAM only**, never data RAM. See `README.md` for the provisional MMIO map and reserved addresses.
- Build/test from workspace root: `cmake -S ttl_forth_emu -B ttl_forth_emu/build`, `cmake --build ttl_forth_emu/build --parallel`, then `ctest --test-dir ttl_forth_emu/build --output-on-failure`. Python 3.8+ is required; CMake generates `build/firmware/forth.flash` and its matching `forth.json` ABI. Focused firmware check: add `-R '^firmware$'` (includes two full native flash saves and may take tens of seconds).
- `ttl_tick()` includes DMA boot ticks; CPU execution begins only after 524288 ticks. `cpu.cycles` excludes DMA and halted debugger checkpoint time.
- `--demo` is a native instruction smoke test, not FORTH. `--flash` requires exactly 512KiB, big-endian instruction words. `--checkpoint` is a halted debugger operation, not the power-failure firmware routine.
- FORTH `SAVE` and the polled power-failure handler run entirely on the CPU, including erase/program/DQ6 polling/readback. Do not replace them with `ttl_checkpoint()`. They require sustained power for the whole operation and are not atomic against an abrupt power cut.
- The firmware keeps `WINDOW=0` and accesses I-RAM/flash through `$FF07`–`$FF0A` address/data ports. NEXT also uses the ports; use `IC@/IC!/FC@/FC!` for atomic FORTH-level transactions rather than separate generic `C!` writes to port latches.
- GUI: `python3 ttl_forth_emu/gui/server.py`, then open the printed loopback URL. It uses `ttl_bridge` via ctypes; GUI keyboard queue is host-side pacing, not additional hardware receive buffering. Video refresh is cooperative and pauses during evaluation/save.
- Native GUI (default build): `ttl_forth_emu/build/frontend/sokol_imgui/ttl_forth_sokol_imgui`. Reuses sibling `gigatron_emu/3rd_party/` read-only, uses Metal/Objective-C++ on macOS, and copies firmware beside the executable. Configure `-DTTL_BUILD_NATIVE_GUI=OFF` for headless/no-C++ builds.
- `firmware/build.py` also generates `forth_abi.h`; never hardcode firmware RAM addresses/key maps in native UI code. Native memory inspectors must read physical arrays, not `ttl_read()` (which consumes keys/toggles flash polling state).
- Native GUI tests: CTest `-R '^native_frontend_controller$'` needs no display; the executable's `--smoke-test` opens a real window, compiles/executes SQUARE via PS/2, then exits. Do not add display-dependent tests to default CTest.
- ASan-instrumented `ttl_bridge` loaded into Python requires preloading the ASan runtime. On macOS Xcode's Python launcher can strip `DYLD_INSERT_LIBRARIES`; use the framework's `Resources/Python.app/Contents/MacOS/Python` executable for that integration test.
- Tests use `CHECK`, not `assert`, so Release builds retain checks. Preserve single-byte PS/2 latch semantics; do not silently replace it with an unbounded host queue.
