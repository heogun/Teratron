# New-machine emulator

- Independent fork of `../gigatron_emu/core/`; do not change the stock emulator. `firmware/build.py` assembles native CPU code plus an I-RAM token-threaded FORTH dictionary; Python/GUI must never evaluate FORTH on the host.
- User decisions: **64KiB unbanked data RAM**, flash stores **I-RAM only**, and **only explicit SAVE** programs it. No power-failure detector/handler/automatic SAVE. Power loss during SAVE is undefined and not a recovery requirement. macOS is the only supported/tested platform.
- Build/test from workspace root: `cmake -S ttl_forth_emu -B ttl_forth_emu/build`, `cmake --build ttl_forth_emu/build --parallel`, then `ctest --test-dir ttl_forth_emu/build --output-on-failure`. Python 3.8+ is required; CMake generates `forth.flash`, `forth.json`, and `forth_abi.h` in `build/firmware/`. Focused firmware check: `-R '^firmware$'`; ISA truth-table check: `-R '^cpu_isa$'`.
- `ttl_tick()` includes DMA boot ticks; CPU execution begins only after 524288 ticks. `cpu.cycles` excludes DMA. The functional model's MMIO/limits are documented once in `docs/emulation.md`; keep that document aligned with core behavior.
- `--demo` is a CPU smoke test, not FORTH. `--flash` requires exactly 512KiB, big-endian instruction words. `--export-flash` only writes current flash bytes to a host file; never make it save live I-RAM.
- SAVE erase/program/DQ6 polling/readback run entirely on the emulated CPU. The obsolete host checkpoint and automatic power-failure save paths were intentionally removed; do not reintroduce them.
- Firmware keeps `WINDOW=0` and uses `$FF07`–`$FF0A` ports. NEXT also uses the ports; use `IC@/IC!/FC@` for atomic FORTH transactions, not separate generic C! writes to port latches. FF05 is reserved, not a power-status register.
- GUI: `python3 ttl_forth_emu/gui/server.py`, then open the printed loopback URL. It uses `ttl_bridge` via ctypes; GUI keyboard queue is host-side pacing, not additional hardware receive buffering. Video refresh is cooperative and pauses during evaluation/save.
- Native GUI (default build): `ttl_forth_emu/build/frontend/sokol_imgui/ttl_forth_sokol_imgui`. Reuses sibling `gigatron_emu/3rd_party/` read-only, uses Metal/Objective-C++ on macOS, and copies firmware beside the executable. Configure `-DTTL_BUILD_NATIVE_GUI=OFF` for headless/no-C++ builds.
- Native normal exit may export already-programmed flash to the executable's `machine.flash` profile (loaded on next launch). This is host file persistence, never an implicit I-RAM SAVE. Smoke tests must ignore and never write user profiles.
- `firmware/build.py` also generates `forth_abi.h`; never hardcode firmware RAM addresses/key maps in native UI code. Native memory inspectors must read physical arrays, not `ttl_read()` (which consumes keys/toggles flash polling state).
- Native GUI tests: CTest `-R '^native_frontend_controller$'` needs no display; the executable's `--smoke-test` opens a real window, compiles/executes SQUARE via PS/2, then exits. Do not add display-dependent tests to default CTest.
- ASan-instrumented `ttl_bridge` loaded into Python requires preloading the ASan runtime. On macOS Xcode's Python launcher can strip `DYLD_INSERT_LIBRARIES`; use the framework's `Resources/Python.app/Contents/MacOS/Python` executable for that integration test.
- Tests use `CHECK`, not `assert`, so Release builds retain checks. Preserve single-byte PS/2 latch semantics; do not silently replace it with an unbounded host queue.
